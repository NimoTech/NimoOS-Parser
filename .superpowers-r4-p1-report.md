# Distill Round 4 — Task P1 report

## Change

`parser/routes/extract.py`:
- docling-native branch (`is_docling_format`): wrapped `DoclingExtractor.load(...).to_markdown(real)`
  in `try/except (ConversionError, RuntimeError)` → `HTTPException(422, f"extraction failed: {exc}")`.
  `ConversionError` imported from `docling.exceptions` inside the branch (lazy, matches existing
  lazy-import style of this module).
- legacy-office branch (`LEGACY_BINARY_OFFICE_EXTS`): changed the existing failure handler from
  `HTTPException(500, ...)` to `HTTPException(422, ...)`, and added `except HTTPException: raise`
  before the broad `except Exception` so any `HTTPException` raised from inner calls passes through
  untouched (defense against the broad catch swallowing it).
- `_safe_resolve`'s own `HTTPException`s (400/403/404) are called before either branch, so they were
  never at risk of being caught — untouched either way.
- Truly unexpected exceptions (anything not `ConversionError`/`RuntimeError` in the docling branch,
  or not caught by the legacy branch's `except Exception`) still bubble as bare 500, unchanged.

## Tests added (`tests/test_routes_extract.py`)

1. `test_extract_corrupt_pptx_returns_422` — writes garbage bytes as `.pptx`, opts the test back into
   the **real** docling converter (undoing the file's autouse `_mock_docling` fixture via a captured
   pre-patch reference to the original `DoclingExtractor.load`), asserts 422 +
   `detail.startswith("extraction failed")`. Verified locally that garbage-content `.pptx` genuinely
   raises `docling.exceptions.ConversionError` (`MsPowerpointDocumentBackend could not load document`).
2. `test_extract_corrupt_docx_returns_422` — same pattern for `.docx`
   (`MsWordDocumentBackend could not load document`).
3. `test_extract_plain_markdown_file_still_200` — plain `.md` never touches docling; confirms the
   422 handling added above doesn't leak into the untouched raw-read path.
4. All 5 pre-existing tests in the file still green.
